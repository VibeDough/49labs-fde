# A 组｜专业名词与缩写

## A1 AI 与 LLM 基础

| 名词 | 全称 / 中文 | 一句话 | 易错点 |
| --- | --- | --- | --- |
| AI | Artificial Intelligence / 人工智能 | 让机器完成需感知、学习、推理、规划的任务这一总方向 | 不等于聊天框，不等于某家产品 |
| 符号 AI | Symbolic AI | 人写死规则（IF…THEN…） | 它也是 AI，但不属于机器学习 |
| ML | Machine Learning / 机器学习 | 从样本与标签中学规律 | "把材料放进对话让它回答"不是训练 |
| 监督学习 | Supervised Learning | 用"输入 + 标签"的样本学规律；分类任务是典型例子 | 标签一致性与历史偏差仍由人负责 |
| 分类任务 | Classification | 把输入判到预设类别之一（如物流/退款/其他） | 要看类别是否正确，误判后果要人定 |
| 推理 | Inference | 用已训练好的模型处理输入 | 与训练（调参数）不同；对话纠错 ≠ 重训 |
| DL | Deep Learning / 深度学习 | 多层神经网络学表示 | "深"指层数，不指思考深度 |
| GenAI | Generative AI / 生成式 AI | 能生成文字/图像/音频/视频/代码 | 与 ML/DL 不是同一分类维度 |
| Transformer | Transformer 架构 | 2017 年提出的深度学习"图纸"，引入注意力机制 | 是架构，不是产品；GPT/混元/DeepSeek 都基于它 |
| LLM | Large Language Model / 大语言模型 | 本质是预测下一个 token 的"文字接龙机器" | 通顺 ≠ 正确；不核实事实 |
| Token | 词元 | 模型处理的最小单位，可为一个汉字、词的一部分或标点 | 也是上下文长度与计费单位 |
| 上下文窗口 | Context Window | 模型一次能读入+输出的 token 上限 | 未超限也可能因输入过长而不准 |
| 幻觉 | Hallucination | 生成流畅但无事实依据的内容 | 接了工具也可能照单全收离谱返回 |
| 温度 | Temperature | 采样随机性；低温更稳定，高温更有创意 | 制度问答/结构化输出用低温 |
| Prompt | 提示词 | 主动喂给模型、可控制的输入文字 | 分系统提示词与用户提示词 |
| System Prompt | 系统提示词 | 用户不可见的人设与规则，可能 > 4000 token | 优化后要核对规则没被删 |
| Memory | 记忆 | 短期＝本次会话；长期＝跨会话绑定账号 | 长期记忆本质仍是"重新组织成文字喂回去" |
| 上下文工程 | Context Engineering | 有策略地组织"该让模型看到什么" | 不是把所有历史一股脑塞进去 |
| CoT | Chain of Thought / 思维链 | 让模型分步骤思考 | 与 RLHF/指令微调共同促成 Agent 时代 |
| RLHF | 基于人类反馈的强化学习 | 让模型稳定"听人话" | — |
| SFT / LoRA / DPO | 微调相关方法 | FDE 需了解原理与适用场景，多数企业需求用不上微调 | 80% 需求 Prompt + RAG 即可 |

## A2 RAG 与检索

| 名词 | 全称 / 中文 | 一句话 |
| --- | --- | --- |
| Embedding | 向量化 | 把文字转成高维数字串，语义相近则向量相近 |
| RAG | Retrieval-Augmented Generation / 检索增强生成 | 先检索资料片段，再把片段+问题给模型生成答案 |
| Chunk | 切片 / 知识片段 | 文档切分后被索引和检索的最小单位 |
| 召回 | Retrieval / Recall | 从库中找出候选片段 |
| Rerank | 重排序 | 对候选片段重新排序，把更相关的排前 |
| 匹配度 | Similarity Threshold | 片段能否进入候选的相关性阈值 |
| 混合检索 | Hybrid Search | 关键词 + 语义结合，适合产品编号/专有名词与自然语言混合查询 |
| 父子级切分 | Parent-Child Chunking | 小子片段用于检索，命中后把父片段给模型，兼顾定位与上下文 |
| 引用 / 溯源 | Citation | 回答标注依据来自哪个文档/片段 |
| Agentic RAG | 智能体检索增强生成 | 基于 Agent Loop，自主反思、切换检索策略、多轮迭代检索 |
| Text-to-SQL | 自然语言转 SQL | 让业务人员用自然语言查结构化数据 |
| 知识投毒 | Knowledge Poisoning | 恶意/错误资料进入知识库影响输出 |

## A3 Agent 与编排

| 名词 | 中文 | 一句话 |
| --- | --- | --- |
| Agent | 智能体 | 给目标后自己拆解、规划、调工具、看结果、再调整的系统 |
| Goal–Action–Observation | 目标—行动—观察循环 | Agent 的核心运转闭环 |
| ReAct | Reason + Act | 思考→行动→观察交错进行，走一步看一步 |
| Plan-and-Execute | 规划—执行 | Planner 拆解、Executor 执行 |
| Reflexion | 反思 | 对过去行为自主改进纠错 |
| Tool Use / Function Calling | 工具调用 | 模型输出结构化调用指令，系统执行并回灌结果 |
| MCP | Model Context Protocol / 模型上下文协议 | 工具调用的统一"普通话"，把多对多适配变一次接入 |
| Workflow | 工作流 | 把固定业务流程编排成节点+连线的可视化流水线 |
| Multi-Agent | 多智能体 | 主 Agent 分发、多个专家 Agent 分工协作 |
| 转交描述 | Handoff Description | 给其他 Agent 看的"什么时候该转交给我" |
| Claw | Claw 模式 | 有独立工作空间、可读写文件/跑代码/调 Skills 的自主任务模式 |
| Agent Harness | 智能体运行底座 | Brain / Tools / Memory / Sandbox / Orchestration 五层解耦 |
| Sandbox | 沙箱 | 隔离执行环境，限制网络、存储、权限与资源 |
| 幂等键 | Idempotency Key | 防重复建单/重复推送的请求标识 |

# B 组｜易混淆概念对照（📌 高频考点）

| # | A | B | 关键差别 |
| --- | --- | --- | --- |
| 1 | AI / ML / DL | GenAI | 前三是"方法层次"，GenAI 是"能力与任务方向"，别硬套包含关系 |
| 2 | 训练 | 推理 | 训练调参数；推理是用已训练好的模型处理输入。对话里纠正一句 ≠ 重新训练 |
| 3 | 会认 / 会判断 / 会生成 | — | 检查方式不同：识别看漏错、判断看类别、生成还要查事实/依据/承诺 |
| 4 | 短期记忆 | 长期记忆 | 短期限本次会话；长期跨会话绑定账号（平台中不按 Session 隔离） |
| 5 | 系统提示词 | 用户提示词 | 前者稳定人设规则且用户不可见，后者是当下具体需求 |
| 6 | RAG | 知识库 | RAG 是技术思路，知识库是平台中承载它的产品能力 |
| 7 | 平台级知识库 | 默认知识库 | 跨应用复用 vs 应用专属；调整引用后需重新发布 |
| 8 | 标签 | 权限 | 贴标签不自动等于访问限制，必须系统侧执行过滤 |
| 9 | 参数提取节点 | 标签提取节点 | 需用户补齐信息用前者（可追问）；给已有内容分类用后者 |
| 10 | 变量聚合 | 语义总结 | 聚合只取非空值，不生成新内容 |
| 11 | 回复节点 | 结束节点输出变量 | 用户看得到靠回复节点；结束节点输出变量用于工作流调工作流 |
| 12 | 连线 | 字段引用 | 连线只表示执行关系，字段要逐项在节点详情核对 |
| 13 | 转交描述 | 提示词 | 前者给其他 Agent 判断"何时转给我"；后者是当前 Agent 的执行规则 |
| 14 | 自由转交 | 工作流编排 | 轻但依赖模型判断 vs 稳定但需明确路由条件 |
| 15 | 连接器 | 工具 | 连"某个系统" vs 做"一个具体原子动作" |
| 16 | 工具 | Skills | 调外部能力 vs 学会一类任务方法 |
| 17 | 标准模式 | 单工作流模式 | 预设稳定问答 vs 固定流程逐步执行 |
| 18 | 智能工作台 | 四种应用模式 | 前者是"我自己用 AI 干活"的个人入口；后者是"搭应用给别人用" |
| 19 | 单次调试 | 批量评测 | 边搭边修 vs 阶段验收，先后衔接不是替代 |
| 20 | 调试成功 | 用户可用 | 工作流调试成功 ≠ 应用能调用；开发态正常 ≠ 用户侧拿到最新版本 |
| 21 | 引用存在 | 答案有据 | 挂了文档名不代表每个结论都被它支持 |
| 22 | 拒答配置 | 权限控制 | 前者约束表达，后者在系统侧阻止越权 |
| 23 | 查询类重试 | 写入类重试 | 前者主要耗时；后者可能重复执行，必须幂等 |
| 24 | 公有云/私有化 | 专属云/混合云 | 公开讲义只提前两种，产品资料另有四种部署形态 |
| 25 | 公开案例成效 | 你的项目成效 | 前者可引用但带出处；后者必须自己评测验证 |

# C 组｜参数与硬约束速查

## C1 文档导入规格

| 类型 | 格式 | 限制 |
| --- | --- | --- |
| 文档 | pdf / doc / docx / ppt / pptx / mhtml / wps / ppsx | ≤ 200 MB |
| keynote / pages | — | ≤ 50 MB |
| 表格/文本 | xlsx / xls / csv / md / txt / html / xmind / json / xml / log / numbers | ≤ 20 MB；≤ 3 万行 / 180 列 |
| 图片（带文字） | jpg / png / jpeg / tiff / bmp / gif | ≤ 50 MB；长宽比 ≤ 1:7 |

导入方式：本地文档 / 网页文件 / 在线协作文档 / 对象存储。网页爬取要求**无需登录授权**、**不支持异步加载**。

## C2 切分规则与常用参数

| 规则 | 适用 |
| --- | --- |
| 默认切分（模型切分，**不支持干预**） | 冷启动、结构规整 |
| 通用标识符切分 | 条款/条目结构清晰 |
| 父子级标识符切分 | 结论与条件分离，需保留上下文 |
| 按行切分（**保留表头范围**） | 每行独立知识的参数表/价目表 |

常用值：切片最大长度 **1000 字符**、重叠 **100 字符**、切片内表格 Markdown / HTML 格式。⚠️ 没有脱离资料结构的万能数值，别抄别人的参数。

## C3 变量隔离表（📌 必背）

| 变量类型 | 用户隔离 | Session 隔离 |
| --- | --- | --- |
| 系统变量（除 `SYS.Memory`） | ✅ | ✅ |
| `SYS.Memory` | ✅ | ❌ |
| 环境变量 | ❌ | ❌ |
| API 参数 / 应用变量 | ✅ | ❌ |
| 工作流变量 / 节点输入 / 节点输出 | ✅ | ✅ |

「用户隔离」>「Session 隔离」；长期记忆由**终端用户 + 应用**唯一确定（A1/A2/B1 互不相通）。

常用系统变量：`SYS.UserQuery`（本轮输入）、`SYS.ChatHistory`（对话历史）、`SYS.Memory`（长期记忆）。

## C4 四种应用模式速选

| 任务特征 | 模式 |
| --- | --- |
| 答案要稳定、有依据、可溯源 | 标准模式 |
| 步骤固定、结果可验收、SOP 明确 | 单工作流模式 |
| 需调研 + 分析 + 复核 + 写作多角色 | Multi-Agent 模式 |
| 需读写文件、跑代码、调 Skills、长耗时、多类产物 | Claw 模式 |
| 低门槛创建 / 一次性临时任务 / 个人办公 | 智能工作台 |

## C5 Multi-Agent 三种协同

| 协同 | 特点 | 硬限制 |
| --- | --- | --- |

## C6 评测配置约束

| 项 | 约束 |
| --- | --- |

| 对比评测 | **仅标准模式应用**；最多 2 组对比模型或 2 组对比提示词 |
| 评测期间 | **锁定知识库**（不可新增/导入/删除/改设置） |
| 裁判模型打分 | 产生 Token 消耗，先验证提示词再跑 |
| 评测任务名称 | 20 字以内、不可重复 |

## C7 其他硬约束

| 项 | 值 / 规则 |
| --- | --- |

# D 组｜疑难问题诊断树

## D1 「回答不准」→ 四环节定位（4.3）

```
知识库里有无可靠答案？
├─ 无 → 补知识（正式资料/问答对/数据库），不要让模型猜
└─ 有 → 打开该条回答实际命中的文档与 Chunk
        ├─ 目标文档未出现 → 查知识状态、检索范围、标签过滤、切分、召回数量与匹配度
        ├─ 目标文档出现但片段缺条件/例外 → 改切分（增大长度/重叠、父子级、表格按行留表头）
        └─ 片段完整却答错 → 查生成侧：Prompt 依据约束、引用要求、变量映射、模型配置
```

**引用异常三类**：没引用 → 查来源展示与输出要求（≠ 没检索到）；引用旧资料 → 查版本与适用范围；引用正确但答案扩展 → 查生成约束，删无依据结论。

## D2 「工作流跑不通」→ 八段定位（4.4）

```
① 触发：工作流启用了吗？应用真的调用了它吗？用的哪个入口和版本？
② 边界：输入/依赖/输出/不能自动处理的情况写清了吗？
③ 追问：用了参数提取节点吗？必填字段和缺失追问配了吗？多值输入有约定吗？
④ 变量：下游实际引用了谁的输出？类型/数组层级/空值对吗？祖先节点关系允许吗？
⑤ 分支：条件表达式用的是哪个变量？大小写、缺失值、易混淆边界样例覆盖了吗？
⑥ 输出：前端/下游要的字段约定了吗？失败状态表达清楚了吗？
⑦ 工具：超时配置、重试次数/间隔、幂等键、接口字段与错误码变更验证了吗？
⑧ 收口：单节点定位后，是否重跑了完整端到端路径 + 补测缺项/分支边界/工具失败/用户中断？
```

## D3 「Multi-Agent 不对劲」→ 按配置项定位（4.5）

| 现象 | 第一站 |
| --- | --- |
| 转交失败 / 某 Agent 永不调用 | 转交描述 + 允许转交对象 → 条件明确则改工作流编排 |
| 执行跑偏 / 输出越界 | 该 Agent 系统提示词 + 工具说明 |
| 乱调工具 / 缺参仍调 | 工具名称是否可理解、入参是否标必填 |
| 返回解析错 | 返回具名 JSON，不要 `[30,1]` |
| 不兜底 | 提示词 + 工具返回**双重约束** |
| 时间戳/编号/格式不稳 | 确定性逻辑工具化 |
| 工作流被当工具调用后中断 | 含选项卡/文件收集/参数提取节点的工作流不要加为工具 |

## D4 「Prompt 改了没用」→ 先判根因（4.2）

| 根因 | 该改哪里 |
| --- | --- |
| 知识没命中 | 知识库 / 切分 / 检索参数 / 问法改写（**不是 Prompt**） |
| 命中了不会用、格式不稳、意图执行不准 | Prompt |
| 复杂推理 / 长上下文 / 工具规划不足 | 模型配置 + 应用模式 |
| 下游解析失败 | 输出格式约束 |

## D5 「用户侧看不到 / 没更新」→ 发布链

```
配置改了 → 是否重新发布？ → 待发布变更项是否包含本次修改？
→ 分享链接是否指向最新版本？ → 是否从用户视角（新窗口/无登录态）复测？
→ 工作流是否启用并设为主工作流？ → 渠道绑定是否被新连接覆盖？
```

# E 组｜常见问题解决方案（FAQ）

## E1 搭建与模式

**Q：客户要"一个 AI 助手解决所有问题"，怎么回？**
A：用 7 维度拆开，第一期只做"能闭环、可验收"的切口。把需求改写成"给定什么输入→得到什么结果→怎样判断做对了"，并把"不做的范围"写进方案画布。分阶段组合模式，不要一期全覆盖。

**Q：标准模式什么时候不够？**
A：需要严格多步流程、表单收集、审批流转、系统写入、复杂条件判断、多工具串联时，改单工作流 / Multi-Agent。

**Q：智能工作台算第五种应用模式吗？**
A：不算。它是"我自己进入工作空间让 AI 干活"的个人入口，也用于自然语言创建应用与辅助搭建；四种应用模式是"搭应用给别人用"。

**Q：模式切换会丢什么？**
A：知识库与工作流范围保留，但**提示词、模型配置等不继承**；Claw 创建后不可切换。切换前先导出配置备份。

**Q：AI 一键优化提示词后效果变差？**
A：优化常删掉拒答规则、引用规则、输出格式。逐条核对再保存，保留优化前版本以便回滚。

## E2 知识库与 RAG

**Q：「库里明明有答案，却答不出来」？**
A：按 D1 四环节走。最常见是问法与文档标题语义距离大（补审核过的问答对/同义词）、切分丢了条件、检索范围/标签过滤设错、引用展示未配置。

**Q：调大召回数量后串进了其他区域/旧版本内容？**
A：先做知识治理（版本、生效期、替代关系、标签），再用服务端身份变量过滤检索范围；调大召回只会在错范围里找更多噪声。

**Q：表格问答数字对不上/单位丢了？**
A：导入前清理合并单元格、重复表头、空行；用按行切分保留表头；导入后逐个检查片段的列名、数值、单位、时间；**统计/聚合类需求改走数据库或 Text-to-SQL**，不要靠召回几行文本。

**Q：新旧制度并存，回答引用了旧口径？**
A：建知识清单（名称/部门/适用对象/生效时间/替代关系/负责人），由业务负责人定口径；旧文档停用/设到期/移出可检索范围但保留归档；**同步检查 FAQ、摘要、培训口径**，否则旧结论从另一入口回来。

**Q：什么时候用 Agentic RAG？**
A：多文档整合、复杂条件筛选、交叉验证、深度推理四类场景。前提：Claw 或 Multi-Agent 应用 + 添加 `AgenticRAGSearch` 工具 + 已导入知识。⚠️ 更耗 Token、更慢，简单问答用传统 RAG。

**Q：改了切分参数但结果没变？**
A：确认解析/切分任务**处理完成**再重新查询；否则是在拿旧检索结果判断。

**Q：模型自动生成的问答对能直接上线吗？**
A：不能，必须人工审核。它可能遗漏限制、误解表格、把条件合并；跨文档答案尤其要业务确认能否组合。

**Q：贴了「华东」标签，华北用户还能看到吗？**
A：默认能。标签必须由应用把**可信身份**映射到检索范围，并在系统侧执行；不能把用户随口输入的部门当授权依据。

## E3 工作流

**Q：单节点调试成功，整条流程却失败？**
A：单节点用的是手工补齐数据，不证明上游能产出、下游能消费。复现原始失败请求 → 找第一个异常节点 → 局部检查 → 修复后重跑完整路径。

**Q：用户只说"我要投诉"，插件就报错？**
A：用了标签提取节点硬补参数。改参数提取节点 + 必填字段 + 缺失追问；开异常处理连到转人工说明。

**Q：最终回复里出现"变量""节点""知识库片段"？**
A：最终回复节点的提示词要写"不要说自己是模型、不暴露内部词"，并把中间策略转成客户可读话术 + 内部处理建议两段。

**Q：用户看不到任何输出？**
A：查是否加了**回复节点**并连到结束节点。只配结束节点输出变量用户看不到。

**Q：四条分支要在下游写四遍逻辑？**
A：用变量聚合取非空输出（如 `branchStrategy`），下游只写一次。注意聚合不是语义总结。

**Q：接口超时重试后建了两张工单？**
A：写入类超时 ≠ 未执行。给业务接口加请求标识/幂等键 + 原请求状态查询；重试设次数、间隔；分别验证正常返回、权限错误、超时、其他异常。

**Q：相近问法走错分支？**
A：补**边界对照样例**（如「什么时候发货」vs「发货要多久」），不要只给正确分支加同义句；检查条件表达式实际引用的变量与大小写。

**Q：语种忽中忽英？**
A：先识别语言输出语言变量供后续节点共享，固定话术准备对应版本；验证混合语言、中途切换与兜底回复。

## E4 Multi-Agent / Claw

**Q：某个 Agent 永远不被调用？**
A：查① 转交描述是否写清"何时转给我" ② 是否勾选允许转交对象。主 Agent 转交描述别写成"负责完成所有方案"。

**Q：完整方案里三个 Agent 各说各话？**
A：后一个 Agent 的输入必须引用前一个 Agent 的输出变量；最后加汇总节点统一结构。

**Q：Agent 生成的时间戳/编号看起来对但不是真的？**
A：确定性逻辑（时间戳、编号、金额计算、格式校验）放到工具/代码/规则里生成，不让 Agent 自由生成。

**Q：工具返回 `[30,1]` 被误读？**
A：改具名 JSON：`{"precision":30,"recall":1}`。工具名称也别叫 `tool_01`，入参标必填、出参具名。

**Q：Agent 不走兜底？**
A：只在提示词写"不支持"不够；顺着工具调用在**返回里也加不支持字段**，双重约束。

**Q：Claw 能删文件/外发邮件吗？**
A：能，所以必须在提示词和系统权限两侧约束：不覆盖/删除/外发原始文件，危险操作先向用户确认；高风险动作进隔离沙箱，凭证与执行环境物理隔离；L3 动作审批 + 回滚 + 人工接管。

**Q：Claw 长任务跑到一半失败要重来？**
A：保存任务目标、计划、已完成步骤、工具结果、中间文件、异常原因，周期性生成状态摘要；失败从最近可靠状态恢复，不从头盲目重跑。

## E5 评测与发布

**Q：什么时候建评测集？**
A：主链路基本稳定、核心场景明确之后。太早建会样本过期、结果难归因。来源优先级：真实业务问题 > 调试记录 > 线上 Badcase > 人工构造。

**Q：评测跑分忽高忽低？**
A：检查评测期间是否有人改了知识库（应锁库）、裁判提示词是否与评测集列匹配、是否同时改了多个变量。每轮只改一个主要因素。

**Q：改完 Prompt 当前题变好，其他题变差？**
A：缺回归。用固定样本复测「同类改善 + 无新问题」，并把线上 Badcase 清洗后回灌评测集。

**Q：开发态正常，用户侧还是旧版本？**
A：查是否重新发布、待发布变更项是否含本次修改、分享链接指向的版本、工作流是否启用并设为主工作流、渠道绑定是否被覆盖。

**Q：设置了兜底回复但模型还是自由发挥？**
A：检查兜底开关是否开启、**联网搜索是否关闭**（课程明确二者冲突），以及知识不足判定条件。

**Q：API 接入后前端解析失败？**
A：核对应用版本、返回格式、前端处理方式是否一致；给下游的输出必须结构化、字段固定、规则明确；失败状态也要有清晰字段。

## E6 安全合规

**Q：提示词写了"禁止越权"，还需要做权限控制吗？**
A：**必须**。Prompt 只约束模型行为，不替代系统层控制。身份校验 → 范围限定 → 权限变量传入检索链路 → 工具最小权限与审计 → 定期复核，五层都要做。

**Q：员工薪资/客户身份信息能直接导入知识库吗？**
A：不能因为"用于知识问答"就全量导入。先做分类分级、使用授权、脱敏、明确可入库字段/可访问人/保存周期；个人信息不得用于模型训练与优化，重要数据不出域。

**Q：免责声明能替代人工复核吗？**
A：不能。法律、医疗、金融、绩效处分等高风险输出只能作辅助信息，必须保留授权专业人员审核与申诉渠道。

**Q：日志能不能无限期全量保存"用于调优"？**
A：不能。日志本身是受保护数据：最小范围采集、脱敏、限访问、定保留周期与删除机制，必要时完成告知与授权。

**Q：新增一个连接器/工具，要不要重新做安全评审？**
A：要。能力变更会改变威胁模型：权限是否仍最小、不可信内容能否触发动作、入参出参是否校验、能否监控调查回滚、留存与事件流程是否覆盖新数据流。

**Q：生产环境出现高风险错误，第一件事做什么？**
A：不是调 Prompt。先确定受影响用户/版本/场景，必要时限制入口、关闭能力或降级人工，保留请求/命中知识/工具调用/输出日志；再根因分析、回归复测、记录、决定恢复范围。

## E7 成本与性能

**Q：Token 成本突然上涨？**
A：查是否开了 Agentic RAG 且反思轮数过高、是否所有请求都路由到大模型、是否有重试/递归/长上下文、定时任务频率是否过高。简单问答用传统 RAG，控制反思轮数，配置限额与配额。

**Q：响应变慢？**
A：查外部接口性能、超时与并发、召回数量是否过大、是否走了不必要的多 Agent 编排；用监控看板定位 P95，而不是凭感觉换模型。

**Q：模型越换效果越差？**
A：平台默认模型是经大量场景验证的最佳实践（尤其多模态问答/阅读理解/Prompt 改写/一键优化模型），不建议随意更换。先基线、再对比调试，判据是"是否遵守提示词、是否引用知识、能否正确选型"。

# G 组｜能力考核高频点速记（📌）

## G1 能力权重与题型

`场景理解与方案设计 25% > 智能体平台核心功能与应用搭建 22% > 行业解决方案 15% > 交付实施评测运维 11% > AI 基础 10% = 安全合规 10% > 产品定位 7%`
`60 题 / 90 分钟 / 70 分通过 / 单选 1.5 分 + 多选 2 分 / 线下 / 证书 2 年`

## G2 一句话必背

1. **LLM 本质**：预测下一个 token；通顺 ≠ 正确 → 幻觉
2. **能力链**：LLM → Prompt → Memory → Embedding+RAG → Tool Use → MCP → Agent
3. **Agent 循环**：Goal–Action–Observation；从模型看仍是"接龙"
4. **企业六大特性**：可控、可测、可审计、可运维、可复用、可集成
5. **五堵墙**：知识、工具、流程、权限安全、评测运营
6. **智能体平台能力地图**：构建模式 × 核心能力组件 × AI Model
7. **模式选型**：稳定问答→标准；固定流程→单工作流；多角色→Multi-Agent；文件/代码/探索→Claw；临时/低门槛→智能工作台
8. **RAG 链路**：导入→解析→切分→向量化索引→召回→重排→引用→维护
9. **四环节调优**：知识可靠 → 切片完整 → 检索命中 → 回答有据
10. **八段工作流排查**：触发→边界→追问→变量→分支→输出→超时幂等→端到端
11. **三大能力**：场景理解 / 交付实施 / 安全合规
12. **五阶段**：接入 → 建设 → 验证 → 推广 → 治理
13. **操作分级**：L1 只读自动 / L2 可逆写入校验留痕 / L3 审批+回滚+人工接管
14. **Prompt 不是安全边界**：即使模型被诱导，系统权限仍要阻止越权
15. **上线不是终点**：运营反馈驱动下一轮配置、逻辑、评测、发布

## G3 十五个易错判断（详见 B 组与 6.3）

标准模式不是万能 ｜ 智能工作台不是第五种模式 ｜ Claw 不可逆 ｜ `SYS.Memory` 不按 Session 隔离 ｜ 环境变量双不隔离 ｜ 回复节点 ≠ 结束节点输出 ｜ 参数提取 ≠ 标签提取 ｜ 变量聚合非总结 ｜ 转交描述 ≠ 提示词 ｜ Plan & Execute 仅单轮且不完整评测 ｜ 对比评测仅标准模式 ｜ 评测期锁知识库 ｜ 兜底时关联网搜索 ｜ Agentic RAG 更耗 Token ｜ 修改必重新发布

       SUM(paid_amount - refund_amount)                        AS gmv,
       COUNT(DISTINCT order_id)                               AS orders,

# K 组｜指标与成本公式速查

## K1 评测指标口径（写进验收报告）

| 指标 | 公式 |
| --- | --- |
| 知识命中率 | 命中正确文档/片段样本 ÷ 总样本 |
| 答案准确率 | 结论与 reference_output 一致样本 ÷ 总样本（数值/条件/例外任一缺失即不一致） |
| 幻觉率 | 含无依据事实或承诺样本 ÷ 总样本 |
| 拒答准确率 | 应拒答样本中正确拒答 ÷ 应拒答样本（误拒另计） |
| 引用正确率 | 引用真能支撑关键结论 ÷ 有引用样本 |
| 格式一致率 | 符合约定结构/字段 ÷ 总样本 |
| 转人工率 / 采纳率 | 转人工请求 ÷ 总请求 ｜ 采纳或复制 ÷ 展示次数 |

## K2 价值、成本、性能

```
月度节省工时 = 日均咨询量 × 可自动解决比例 × 单次人工耗时(分) ÷ 60 × 工作日
月度毛收益   = 月度节省工时 × 人力分钟成本
月度总成本   = Token/PU + 平台订阅 + 运维人力 + 知识维护人力
净收益       = 毛收益 − 总成本
回收期(月)   = 一次性实施投入 ÷ 净收益

单次成本 ≈ (输入 token × 输入单价 + 输出 token × 输出单价) × 检索/反思轮数
月度成本 ≈ 单次成本 × 日均调用量 × 工作日 × 峰值系数
端到端延迟 ≈ 接入 + 检索 + 重排 + 模型首字 + 生成 + 工具调用 + 输出校验
并发上限   ≈ min(模型配额, 接口 QPS, 数据库连接池, 平台限流)
```
**三条纪律**：基线先量；只算可归因的节省；不套用公开案例成效数字。

## K3 场景评分卡

`加权总分 = 价值×0.35 + 可行性×0.25 + 数据就绪×0.25 + 风险可控×0.15`（各 1–5 分）
**价值高 ≠ 优先做**：数据没就绪、风险不可控的高价值场景最易翻车。

# L 组｜对外表达与讲解速查（讲给别人听）

> 现场可抄版。完整方法论见主手册第八篇。核心原则：**先讲边界和验收，再讲能力；先讲风险，再讲效果。**

## L1 一句话定义（背下来）

> FDE 是把企业级智能体**从「能用」做到「可验收、可上线、可治理」**的人：判断场景值不值得做 → 选构建模式接入知识与流程 → 用评测集证明效果 → 用权限、审计与运维管住风险。

## L2 三种时长脚本

| 时长 | 骨架 | 收口句 |
| --- | --- | --- |
| 30 秒 | 是什么 → 解决什么 → 怎么证明 | 「不看演示好不好看，看命中率、越权能不能拦、能不能回滚」 |
| 3 分钟 | 场景边界 → 模式选型 → 验收指标 → 三条风险 | 「验收用 40 条评测集，不靠演示」 |
| 10 分钟 | 价值 → 架构 → 演示 → 评测 → 计划 → 风险 | 「结论来自评测报告，遗留问题写在材料里」 |

## L3 术语翻译（行话 → 一句人话）

| 行话 | 一句人话 |
| --- | --- |
| RAG | 先翻制度文件再开口，还会说是从哪条来的 |
| Embedding | 按意思找，不按字面找 |
| Chunk | 把长文件拆成能引用的小段，太碎会断章取义 |
| Rerank | 先粗筛，再把最相关的三条给模型 |
| 幻觉 | 没依据时要说不知道，而不是猜 |
| 系统提示词 | 岗位说明书：是谁、能做什么、不能做什么 |
| 工作流 | 把 SOP 固化成能查到每一步的步骤 |
| 工具 / MCP / 连接器 | 统一接口调业务系统，不用来回复制粘贴 |
| Multi-Agent | 一个拆任务，几个分别查资料、算数、写稿 |
| 评测集 / 回归 | 上线前的考卷，以及每次改动的复考 |
| 裁判模型 | 自动阅卷，再人工抽查校准 |
| 幂等 / 回滚 | 网络抖动不会生成两张单，出错能撤回 |
| RBAC / 最小权限 | 按岗位给权限，不默认全开 |
| 灰度 / 降级 | 先给 5% 的人用，指标不对切回人工 |

## L4 四类听众开场句

| 听众 | 开场句 |
| --- | --- |
| 业务负责人 | 「原来查 3 个系统填 2 张表，现在一次给出带出处的建议，仍由你确认后提交」 |
| 技术负责人 | 「所有写入带幂等键、结构化返回、审计留痕，失败可重放可回滚」 |

## L5 质疑应答 12 条（极简版）

| 质疑 | 一句应答 |
| --- | --- |
| 不就是聊天机器人 | 接了私有知识有出处、能按 SOP 调系统、行为可审计可回滚 |
| 会瞎编怎么敢用 | 知识边界 + 无答案拒答 + 引用可追溯 + 高风险人工复核 + 红队用例 |
| 直接上最自主的 | 越自主越难验证，按约束选模式，成本与可控性一起算 |
| 效果怎么衡量 | 用评测集不用演示，给基线、口径、回归记录，接受抽检 |
| 数据会被训练吗 | 分级、不出域、不用于训练优化、留存删除策略、审计字段 |
| 上线后谁负责 | 监控、Badcase 闭环、变更评审、回滚点、责任人矩阵 |
| 接这么多系统工期长 | 先做 MVD：一个场景、最小接口集、明确停止条件 |
| 换平台白学了 | 方法论与验收不变，只换参数表（主手册 0.6 迁移三步） |
| 成本会不会失控 | Token / 延迟 / 并发测算 + 降级策略 + 预算阈值告警 |
| 业务方不用怎么办 | 推行是交付的一部分：Workshop、培训、采纳度、抵制应对 |
| 合规能过吗 | 提供检查框架与红队报告，由客户法务判定，不替客户承诺 |
| 数据是真的吗 | 演练 / 公开案例 / 实测三类分别标注，不混用 |

| 四步怎么用 | 找模块 → 选角度 → 复制 → 粘贴到任意 AI | 提示词已写明资料版本、册、章节、认知层、能力域、关键概念、核心问题、产出物与出处锚点 |
| 怎么判断 AI 的回答 | 输出要求 | 必须区分【手册已写明】【AI 的推断】【需查当期官方文档或客户确认】；结尾给可验收产出物与 3 个继续追问 |
| 哪些内容不能信 | 禁止项 | 未经核实的成效数字、价格、性能实测、合规资质结论、真实客户案例；产品名只作能力举例，不构成推荐 |
| 上下文不够怎么办 | 提示词末段 | 要求 AI 先列出需要补充的信息，不要替你补全业务背景 |
| 想批量检索 / 打印 | 独立提示词库页 | 按资料 / 认知层 / 追问角度 / 关键词筛选，逐模块复制；打印时提示词一并输出 |
| 本地环境复制失败 | 弹窗「全选」 | 剪贴板 API 不可用时自动降级为全选复制；也可手动 Ctrl/Cmd+C |
| 会不会上传内容 | 边界 | 提示词在本地浏览器生成，复制只写剪贴板，页面不发起任何网络请求；AI 回答不替代本手册与客户验收 |

> **与 N7 的关系**：N7 解决「我在哪、怎么回去」，N8 解决「这一节怎么继续问」；
> 追问是附在**每个学习点**上的横切能力，不是一个新的知识板块。
> 主手册 C.11 给出完整设计（模块划分 / 五角度 / 输出约束 / 交互 / 边界）。

### O2 五维选型矩阵（一票否决优先于加权）

| 维度 | 建议权重 | 一句话 |
| --- | --- | --- |
| 能力与质量 | 30% | 在我的评测集上达标率多少 |
| 成本与效率 | 25% | 缓存命中价 + 输出价 + 重试放大 + P95/P99 |

| 工程可集成性 | 15% | 流式、Function Calling、结构化输出、SDK 兼容 |
| 可持续性与退出 | 10% | 升级是否破坏兼容、能否换模型不重写业务 |

> 数据必须不出域、必须有商用许可、必须支持流式等属于**一票否决项**，不满足直接淘汰。

### O3 成本四笔账

1. **KV Cache 命中价**（Agent 长会话的关键是命中率，不是标价）；2. **输出价 × 实际输出长度**（推理模型思考 token 很长）；3. **重试与兜底放大**（超时/429/格式错）；4. **自部署全成本**（GPU 折旧 + 电费 + 运维 + 升级回归人力，不能只算硬件）。

### O5 从零搭 Agent 八步

判定形态 → 写工具契约 → 手写最小 Agent Loop（Goal–Action–Observation）→ 加检索 → 加记忆与上下文工程 → 加护栏 → 加可观测 → **最后才上框架**。

### O6 评测必背

- **4-tuple** 缺一不可：request / environment（工具与知识库版本）/ stopping criteria（步数与超时）/ scorer（规则 / 代码 / 裁判 / 人工）。
- **pass@k** = k 次至少一次成功（能力上限，可重试场景）；**pass^k** = k 次全部成功（生产稳定性，对外 SLA 看这个）。
- 裁判模型四类偏差：位置偏差、长度偏差、自我偏好、评分漂移；pairwise 要交换顺序做两次。
- **评测期间锁**：模型 / 知识库 / 提示词 / 温度 / 工具 schema 全冻结，否则无法归因。
- 五类必测失败：工具调用、检索（含两个答案打架）、循环失控、注入越权、长时任务恢复。

### O7 优化顺序（从便宜到贵）

数据清洗 → 上下文工程 → 工具契约 → 检索链路 → 自动提示优化 → 最后才考虑 SFT / 蒸馏 / RL。任何优化都用同一评测集 + 同一口径验证并保留可回滚版本。

## P 组｜语音与 TTS 选型速查（v5.0 新增）

> **入口**：主手册第十三篇。**所有时延/价格/显存均为公开报道或厂商文档口径，必须用真实语句集在自己的环境压测。**

### P1 先定四个产品约束（比「哪家音质好」更早决定架构）

是否要打断（barge-in）｜是否接电话线路（SIP/PSTN）｜数据是否必须不出域｜是否要定制音色 / 声音克隆。

### P2 全链路与预算

`VAD → ASR → LLM 流式 → 分句 → TTS 流式 → 播放器 buffer → 用户听到`。
公开拆解参考：传输 40ms + ASR 100ms + LLM 首 token 150ms + TTS 首音 120ms + buffer 40ms ≈ **450ms 端到端**【公开报道口径】。**TTS 只是其中一段。**

### P3 方案谱系

| 类型 | 适合 | 不适合 | 必查 |
| --- | --- | --- | --- |
| 国内商业流式 API | 中文主力、要 SLA、要字级时间戳 | 数据必须不出域 | 首包口径（不同接口 300ms / 600ms 两类）、计费单位、SSML 是否计字符 |
| 海外商业 API | 多语种、有免费额度可验证 | 跨境合规敏感、中文为主 | 跨境数据、中文自然度、Flash 与高保真型号区别 |
| 开源流式轻量 TTS | 私有化、离线、批量、控成本 | 无 GPU 团队、高峰 SLA | **License 逐款核对**、显存、流式支持 |
| 非流式克隆型 | 离线配音、有声内容 | **实时 Agent**（首包数秒） | 不要放进实时链路 |
| 编排框架 | 换厂商不改业务、语义轮次检测、电话接入 | — | 是否支持所选 ASR/TTS、能否自托管 |

### P4 决策树（背下来）

`必须不出域？→ 是：开源自部署（先查 License/GPU），实时选流式轻量型号；否：看是否电话/高并发/SLA → 商业 API。任何分支都要用真实语句集压测。`

### P5 评测八指标

首包时延 TTFA（P50/P95 + 文本长度 + 并发 + 是否冷启动）｜RTF｜MOS｜字错率/多音字/数字读法（含业务专名）｜字级时间戳｜长文本音色一致性｜**端到端轮次时延**｜打断成功率。

### P6 延迟优化五招（收益排序）

1. **TTS-on-partials**：LLM 出第一个完整句子就送 TTS（省 200–300ms，收益最高）；2. 语义端点检测替代静默超时 VAD（省 100–250ms 且少抢答）；3. 全链路流式 + 长连接复用；4. buffer 500ms → 50–150ms；5. 预热音色防冷加载。【公开报道口径，均需自测】

### P7 合规六条

声纹书面授权（用途/期限/可撤销/留证）｜深度合成标识｜音频与文本是否用于训练、留存与删除｜电话录音告知与 PII 脱敏｜禁止克隆音色冒充真人办业务｜业务词典与音素标注回归集（每次模型升级重跑）。

### P8 降级阶梯

主 TTS 超时 → 备用 TTS → 预录制关键话术 → 转文本 → 转人工。每级写清触发阈值与用户提示；高频固定话术预合成缓存。

## Q 组｜开源课程精读与跨行业案例速查（v5.0 新增）

> **入口**：[《03_开源课程解读.html》](03_开源课程解读.html)（独立第三册）、主手册第十四篇、`参考资料/开源课程原文/`。

### Q1 开源书一句话与因果链

《前线部署工程师》（范冰，<https://fde4.ai/book/>）讲**这门生意怎么成立**，我们手册讲**系统怎么做出来**。
链条：模型商品化 → 价值在客户现场 → 选对问题 → 赢得客户 → 激活 → 续约 → 扩张 → **规模化复制（分水岭）** → 案例与指标 → 伦理边界。

### Q2 18 张方法卡（背关键词即可）

鸿沟 / 演示循环 / 记账方式（定制记产品发现）/ **PSF 三关**（痛点·经济性·可行性）/ 毕业标准 / 三类高危信号（无主之地·只许看不给碰·宇宙级需求）/ 影子工作法（看变通不看流程）/ **MVD 三军规**（真实数据·缩范围不缩价值·周级截止）/ 读旧写新（数据兼容·架构不寄生·流程顺从人）/ 灯塔客户 / **五份地图**（数据·流程·组织·系统·政治）/ 激活≠上线 / 热修复 / 评估体系（业务方当评委）/ **健康分**（使用·价值·关系·商业）/ 按结果收费四档 / **三级杠杆**（手册·组件库·平台）/ 六条底线。

### Q3 必须记住的口径纪律

- **【原书引用】**：数字来自开源书，未独立核实，引用时保留「原书引 X」。
- **【公开报道】**：媒体/厂商/白皮书，注明来源与日期，多为披露方自述。
- **【当期核对】**：价格、版本、时延、许可证、资质，落地前查官方文档或客户确认。
- **三问**：分母是什么？判定窗口多长？谁来判定？
- **禁止**：把上述数字写成我们的实测结论、推荐理由或承诺值。

### Q4 五份地图最易漏的点

数据地图看「**哪个被信任**」而非「有什么」｜流程地图看变通与三个情绪点位｜组织地图找「知识枢纽」｜系统地图问「客户发版要几周」｜**政治地图最常被漏**，要提前给受损者「新生路」。

### Q5 按结果收费四档与三问

按用量（追踪成本非价值）→ 按任务（有业务含义）→ 按结果（已解决会话 / 启用产线门店 / 英亩数）→ 按价值分成（归因最难）。
引用任何解决率/分流率前问：分母、判定窗口、谁判定。

### Q6 三级复制杠杆与产品化四问

手册管判断、组件库管手艺、平台管能力；可验证指标是**定制递减率 / 交付资产复用率 / FDE 人均产能**。
产品化四问：是个性还是共性（**三个以上客户独立出现**）、抽象到哪层、谁长期负责、平台化后现场还剩什么判断。

### Q7 六条职业道德 → 两条工程修正

数据主权｜诚实报告坏消息｜不制造依赖不贩卖恐惧｜把被替代的人当回事｜敢对不该做的事说不｜代表技术本身。
工程修正 ①：最小权限不只是规范，是操守；② **人在回路会疲劳**——原书引公开复盘「事事弹窗时用户照批约 93%」，所以护栏要分级，只对真正高影响动作弹窗并给出关键证据。
